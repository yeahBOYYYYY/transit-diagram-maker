# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Transit Diagram Maker: a grid-based vector editor for metro maps. The spec is `docs/requirements.md` (a "Photoshop-like" dark UI is a top priority there). Rust core → WebAssembly, Vue 3 + TypeScript front end in `web/`.

`docs/bugs.md` is the user's bug list, one dated section per commit hash (newest first). "Fix the bugs for this commit" means the section for the current `HEAD`; ask when an item leaves the fix open.

## Commands

Rust (from the repo root):
```bash
cargo test                                   # all Rust tests
cargo test -p transit-core --test editor     # one integration test file
cargo test -p transit-core pill              # tests whose name matches "pill"
INSTA_UPDATE=always cargo test -p transit-core --test render_snapshots   # rewrite the SVG markup snapshots after an intended rendering change (or `cargo insta review`)
cargo clippy --all-targets                   # expected to be warning-free
```
Do not run `cargo fmt`: the code is not rustfmt-clean (long lines, compact literals, no `rustfmt.toml`), so it rewrites nearly every file. Match the surrounding style by hand.

Web (from `web/`):
```bash
npm run build:wasm      # REQUIRED after any Rust change: regenerates web/src/wasm/pkg (gitignored)
npm run dev             # http://localhost:5173 ; on WSL with the repo on /mnt/*, use VITE_POLL=1 npm run dev
npm test                # vitest: tests/unit, tests/component (Testing Library) and tests/integration; loads the real wasm via initSync in tests/unit/setup.ts
npx vitest run tests/unit/tools.spec.ts -t "eraser"   # single file / test name
npm run typecheck       # vue-tsc
npm run build           # typecheck + vite build to web/dist
npx playwright test                         # e2e (tests/e2e), starts its own vite on :5174
npx playwright test editing -g "rotate"     # single e2e file / test
npm run screenshots                         # regenerate the README screenshots in docs/images (skipped in normal runs)
```
Playwright uses the locally installed Google Chrome (`channel: 'chrome'`); `PW_CHANNEL=chromium` switches to the bundled browser. Unit and e2e tests both need the wasm package built first. Outside CI the e2e config reuses a server already listening on :5174, so a leftover vite (e.g. started with `npx vite` and killed only at the `npx` level) can serve stale code; kill stray `vite.js` processes if tests behave as if your change isn't there (`pkill -f '[v]ite.js'`: a plain `pkill -f vite.js` also matches, and kills, the shell running it).

Tests never compare screenshots, so they pass the same on every machine and in CI. The drawing is pinned down by `insta` snapshots of the SVG markup (`crates/transit-core/tests/render_snapshots.rs`, `.snap` files in `tests/snapshots/`), the e2e tests check menus and dialogs with Playwright ARIA snapshots (`toMatchAriaSnapshot`) and the canvas against the engine fragments (`tests/e2e/structure.spec.ts`). `crates/transit-core/tests/properties.rs` holds `proptest` property tests; keep its `properties.proptest-regressions` file committed, since it replays inputs that once failed. Component tests in `tests/component` use `@testing-library/vue` + `user-event` (query by role or label, not by CSS class); `@testing-library/jest-dom` matchers are loaded in the setup file.

CI (`.github/workflows/ci.yml`) runs clippy with `-D warnings`, `cargo test`, the wasm build, `npm test`, `npm run build` and Playwright on every pull request. `release.yml` reruns it on every push to `main` and publishes a GitHub release `v<version>` from `web/package.json` (which must equal the Cargo workspace version), skipping it when that tag exists.

Unit tests run components in happy-dom, which can crash while patching `OptionsBar` from one tool's branch to another (real Chrome is fine); mount a fresh component per tool instead of switching tools on a mounted one.

## Architecture

**The Rust engine owns the document; the web app is a view over it.** `crates/transit-core` holds the model, geometry, history, rendering and I/O. `crates/transit-wasm` is a thin `wasm-bindgen` wrapper where structured data crosses as JSON strings and ids as `f64` (to avoid JS `bigint`). `web/src/core/engine.ts` (`Engine`) is the typed TS mirror of that API, and `web/src/core/types.ts` mirrors the serde types. When you change a Rust type or API, update all three layers.

Core concepts (`transit-core`):
- **Everything is in cell units.** A cell `(x,y)` has its center at `(x+0.5, y+0.5)`. Lines are lists of *turning* cells whose consecutive points are 8-way aligned; `geom::normalize_path` routes, dedups and compresses them. Pixels only appear at render time (`× DocSettings::cell_px`, which is never saved): the canvas always uses `CELL_PX` = 24 (`web/src/core/viewport.ts` mirrors it) and an SVG export may pick its own scale (`render::export_svg_with`). Free positions (icons, station offsets, Alt-moved text) are stored with 0.1-cell precision (`Vec2::snapped`). Rotations snap to multiples of 45° (`editor::snap_rotation`); with Alt (`rotate(.., free = true)`) text and icons turn by whole degrees (`editor::free_rotation`, which also keeps typed angles), while lines and stations always stay in 45° steps. Lines turn run by run (`editor::grid_rotation`): every unit step turns by the same angle, so at 45° a straight run of n cells becomes a diagonal run of n cells and the shape is kept (rotating cell centers geometrically would stretch it by √2); stations on those cells move with them. Everything snaps by default: a non-free `translate` puts whichever corner of a text box is nearest to a grid intersection on it (`TextBox::snap_corner`) (except a label moved along with its station, which keeps its place beside it), and moves icons in whole cells next to grid content or puts their top-left center on a cell center on their own; Alt (`free = true`) moves in tenths. New text goes on the nearest intersection (`tools::placeTextAt`), new icons on the cell center (`tools::placeIconAt`).
- **Text boxes** (`model::TextBox`): `pos` is the top-left corner and the box rotates around it. The text is `paragraphs` of `runs`; a run's `RunStyle` values (font, size, color, bold, italic) and a paragraph's `align` are optional overrides of the box values, tidied by `TextBox::normalize`. A box property patched without `paragraphs` (the Properties panel, nothing selected) clears that override everywhere (`update_content`). `width` is the widest line: Rust only estimates it, and `CanvasView::fitTexts` measures the `tspan[data-line]`s after every render and stores the result with `fit_text_widths` (not recorded in the history). A width change keeps the corner fixed, except for station labels, which keep their aligned edge next to the station (`TextBox::set_width`). `web/src/core/richtext.ts` edits the same model by character range and renders/reads the inline editor's DOM.
- **Layer tree** (`model.rs`, `tree.rs`): `Document.root` is ordered **bottom-to-top** (later = painted on top). `Editor::tree()` returns the reverse, top-first order that the layers panel shows. `move_node`/`restack` indices are bottom-to-top; `web/src/core/tree.ts::stackIndex` converts between the two. Group roles: `Line { line_id }` (all segments and stations of a line), `Station` (a station plus its label), `Generic`. Empty Line/Station groups are auto-pruned; generic groups are kept.
- **Stations:** `Station::offset` is a free displacement from the line cell set by Alt-drag (`translate(.., free = true)`); a normal move snaps the station back and clears it. Ticks sit in a cell corner (`along` = -1/+1, centered on diagonals, see `geom::tick_center`). Pills are a set of cells edited with `set_pill_cells` (must stay 8-connected and touch a line). A tick follows its line's color: recoloring a line (`editor::recolor_line`) also recolors the ticks that still had the old color, and a station turned into a tick takes the line color.
- **Line identity:** every segment carries `line_id`. Erasing splits one segment layer into several layers with the same `line_id`. Each segment has its own style, so a line can change style along its way, but the color is shared: a color patch to one segment recolors the whole line (`Editor::update_content`), and `Editor::update_line_style` patches every segment (used when the line group is selected). Segments joining another line keep their style and take its color. Stations reference `line_ids` and are re-snapped onto their line after transforms. Labels (`TextBox.station_id`) follow a moved station unless the label itself was also moved.
- **History** (`editor.rs`): every mutation goes through `Editor::apply`, which snapshots the whole `Document`, rolls back on error, and records only if something changed. Drags use transactions: `begin()`, then on each move `rebase()` + re-apply the absolute delta, then `commit()` (or `cancel()`). That is why a drag, an erase stroke or a slider scrub is one undo step. Group expand/collapse deliberately bypasses history.
- **Rendering** (`render.rs`): the same SVG markup feeds the live canvas (`render_fragments`, one fragment per visible leaf) and `export_svg`, so the canvas and the export match. Line caps are separate filled shapes (roundness comes from `cap_roundness`). Stroke kinds are plain, hollow (an `inner_color` channel) and inner dashed (a plain line with `inner_color` dashes down its middle); dash patterns are fitted so the dashes start and end with a full dash, and `dash_start_offset`/`dash_end_offset` keep the ends plain (`geom::dash_array`). Text is one `<tspan data-line>` per paragraph, positioned from the box corner, with a nested `<tspan>` per formatted run; a line is `LINE_SPACING` × its largest size tall with the baseline at `BASELINE`. Text `align` is visual (start = left) even for `direction = rtl`, so `text_svg` swaps the SVG anchor. Dot and pill stations are a "blob skeleton" stroked with round joins (a Minkowski sum, giving a constant-radius outline). Diagonal links are skipped when an orthogonal neighbor already bridges the two cells, and 2×2 blocks are filled.
- `.transit.svg` (`io.rs`) = the SVG export at 24 px per cell plus the editor data: each layer-tree `<g>` starts with a `<transit:group|segment|station|text|icon|shape>` element (namespace `io::NS`) holding the node as attributes (a text's paragraphs and runs are `<transit:p>`/`<transit:run>` children, written without whitespace); settings and uploaded icons sit in `<metadata><transit:document>`, fonts in `<style transit:font=…>`. Reading and writing are hand-written (no serde), so a new model field must be added to both `io.rs` functions. Enum attributes go through their serde names (`enum_name`/`enumeration`). The app isn't released yet, so format changes need no migration or serde aliases. `validate` repairs ids, settings and paths on load. SVG export options (scale, margin, background) are `ExportOptions`, kept in the web preferences, not in `DocSettings`.
- **Shapes** (`model::Shape`, drawn with the shape tool): a free-standing straight line, rectangle or circle (`ShapeGeometry`, serde tag `shape`, flattened like a station's shape) with a shared paint (`color`, `filled`, `border_color`, `border_width`). They snap like the rest: a non-free `translate` (`Shape::snap_delta`) puts the line end or rectangle corner nearest to a grid intersection on it and a circle's center on a cell center; `rotate` turns an on-grid line run by run like a transit line (`rotate_offset`) and a rectangle around its center. `editor::tidy_shape` keeps the numbers in range on every change, and keeps a rectangle's `rotation` in (-45°, 45°] by swapping its width and height (a quarter turn). Borders of rectangles and circles are drawn inside the edge, so they keep covering their cells. The tool's drag-to-shape rules live in `tools::shapeFromDrag`, the defaults per kind in `prefs.shape`. In move mode a single selected shape shows resize handles (`tools::shapeHandles`: line ends, rectangle corners, the corners of a circle's box); the selection tool drags one as a transaction of `updateContent` patches from `tools::resizeShape` (the opposite corner, or the other end, stays; a circle keeps its center).
- **Uploaded assets** (`assets.rs`): fonts (base64 data URLs behind `Arc<str>` so undo snapshots stay cheap) and SVG icons live in `Document.assets`. Uploaded SVG is untrusted and goes through `assets::sanitize_svg` (an element/attribute allowlist) on upload and on load; never render user SVG that skipped it.

Web app (`web/src`):
- `stores/editor.ts` is the central reactive store, used as a singleton via `useEditor()` / `provideEditor()`. Mutate through `store.run(e => …)`, which calls the engine, refreshes the mirrored `fragments`/`tree`/`settings`, and turns thrown engine errors into a status-bar message. Selection, view, tool, overlays and text-edit state live only in TS.
- `core/actions.ts` is the catalogue of every user action (labels and default shortcuts). `stores/commands.ts::runAction` implements them; the menu bar, the keyboard handler and the shortcut editor all go through it. Add new commands there.
- `tools/index.ts` holds each tool's pointer/keyboard behavior as plain objects. Each tool has its own button in `ToolsPanel` (no shared slots or flyouts). There is no icon tool: pictograms are added from the Icons panel (click adds one in the middle of the view, drag places it), which also holds the defaults for new pictograms; e2e tests use `dropIcon` in `tests/e2e/helpers.ts`. `components/CanvasView.vue` dispatches events to the active tool. It does hit-testing with `elementsFromPoint` on `g[data-id]` fragments (falling back to the boxes of text and pictograms and to the distance from thin straight-line shapes), measures selection bounds with the engine's `Fragment.bounds` (`render::content_bounds`: exact for stroked lines and stations, which `getBBox` measures without the stroke, and the real text box rather than the font's glyphs) and with DOM `getBBox` only for pictograms, and handles the global keydown. The canvas captures the pointer on press, so `dblclick` reuses the handle recorded at `pointerdown`.
- `stores/prefs.ts` holds app preferences, shortcuts and tool defaults, persisted to localStorage. These are separate from the document settings, which live in the Rust `DocSettings` and are saved and undoable. `loadPrefs` deep-merges stored values over the defaults and drops unknown keys, so removing a pref or shortcut needs no migration; a line kind that no longer exists falls back to the default. Magic numbers belong in prefs (with a field in the tabbed `PreferencesDialog`, whose `TABS` list says which keys each tab restores); `resetPrefs` restores everything (Edit ▸ Restore All Defaults) and `resetWorkspace` only the panel layout.
- Inline text editing (`state.textEdit`) is one engine transaction: `startTextEdit` begins it (the text tool begins it before creating a new text), every keystroke writes the whole draft with `updateContent`, and `finishTextEdit` commits or cancels. The editor is a `contenteditable` laid out exactly like the box; formatting from the options bar or Properties panel goes through `store.formatText`, which applies to the selected characters (or the whole box when nothing or everything is selected). Panels that format the edited text carry `data-keeps-text-edit` so focusing them doesn't end the edit, and their buttons use `@mousedown.prevent` to keep the selection.
- `PropertiesPanel` is one CSS grid (label | input | the rest): `NumberField`s place their label, input and unit in those columns, other properties are `.prop` rows (a `.lbl` with its `HelpTip`, then a `.ctl`), and grouping wrappers use `display: contents`. Every property is a row of its own, so all values line up; don't put two fields side by side.
- `OptionsBar` scrolls sideways when a tool's options don't fit (hints shorten first), so put the always-needed options (like line caps) before the style-specific ones.
- `LayersPanel` follows the selection like Photoshop: whatever gets selected (usually a click on the canvas) has its collapsed ancestor groups expanded (engine `setExpanded` + `store.refresh()`, so it is neither an undo step nor an unsaved change) and its row scrolled into view.
- The upper dock panel is one tabbed `PanelFrame` (Properties | Icons, `state.dockTab`) created in `App.vue`; `PropertiesPanel` and `IconsPanel` are its bodies and have no frame of their own.
- UI wording: every user-visible string spells words out, units included ("Line width", "Largest zoom", "pixels", "milliseconds", not "Line W", "Max zoom", "px", "ms"). Ordinary English contractions are fine. This also applies to Rust error messages, which reach the status bar.
- The two swatches under the tools in `ToolsPanel` are `prefs.line.color` and `prefs.line.inner_color`, used like Photoshop's foreground and background colors (`color.swap` = X, `color.reset` = D).
- Every `ColorField` has an eyedropper (`core/eyedropper.ts`): the next click takes the color painted on the canvas (or any `[data-swatch]` element) and is swallowed so it doesn't reach a tool.
- Every property shown in the UI has help text in `core/help.ts`, displayed by `HelpTip` (NumberField/ColorField take a `help` prop); add an entry for any new property. A unit test checks the Properties panel, dialogs and tool options for missing ones.
- `window.__transit` exposes the store; e2e tests use it to read state and to convert cells to screen coordinates (`tests/e2e/helpers.ts`). `openApp` removes `showSaveFilePicker`/`showOpenFilePicker` so saving and opening use the download / `<input type=file>` fallbacks Playwright can drive; tests that need the File System Access path install a fake picker.

## Git workflow

`main` = releases, `dev` = integration. New work goes on `feature/*` and fixes on `bugfix/*`, each branched from `dev` and merged back with `--no-ff`. Exception: fixing a `docs/bugs.md` section is one commit directly on `dev` ("Fix the bug list for commit <hash>") that also includes the user's uncommitted edits to `docs/bugs.md`.
